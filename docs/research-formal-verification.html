Testing is not proof.

Formal verification proves, mathematically, that software meets its specification for every input and every reachable state. As AI writes more of the code behind identity, capital and governance, it is how institutions keep the right to trust what they run.

The premise

Tests sample behaviour. A proof covers every case.

Passing tests shows software behaved correctly in the cases someone examined. Hidden logic flaws, race conditions and vulnerabilities can still be there.

Formal verification states the required behaviour as a specification, then proves no input, operation or reachable state can break it. A small checker confirms the proof.

Trust the specification, not the code.

The trust model

Human intent, machine proof.

Vericoding has AI generate formally verified code from a formal specification. Vibe coding generates plausible code from a prompt. In both, the machine writes the code; only vericoding produces something a checker can confirm. The human role moves from writing code to defining truth, constraints and intent.

  1. 01 · Specify

    Humans define truth

    Intent, constraints and governance are written as a formal specification. “Users only access their own data” becomes a logical rule, not a sentence.

  2. 02 · Implement

    AI writes the code

    The implementation is generated against the specification. How much code there is stops mattering, because nothing ships on the strength of review alone.

  3. 03 · Prove

    AI writes the proof

    Alongside the code comes a machine-checkable proof that no input, operation sequence or reachable state can break the rule.

  4. 04 · Check

    A small checker decides

    A lightweight proof checker accepts or rejects the proof. What is left to trust: the specification, the checker and the mathematics.

Proof languages

Four ecosystems.

From the paper’s appendix. Each blurs the line between mathematics, specification and executable software.

  • 01

    Lean

    Theorem proving and practical programming in one language. The strongest fit for AI-generated proofs and verifiable governance.

  • 02

    Rocq (formerly Coq)

    Decades of high-assurance use in compilers, kernels and cryptography. Suited to SSI protocols and trust registries.

  • 03

    Agda

    Proofs as programs, with an elegant dependent type system. Best for research and declarative models.

  • 04

    Idris

    Dependent types for everyday code, so impossible states become unrepresentable in agent runtimes and APIs.
